## Edge cases / inbound webhook status machine

| Severity | Area | Finding |
|:---|:---|:---|
| critical | codebase | **`apply_keycloak_user_disabled(enabled=False)` always sets `user.status = suspended`** (`keycloak_provisioning.py:213–214`), with no guard on current status. Enable path only maps `suspended`→`active` (`:210–212`). Findings edge case 2 claims the outbound PUT echo is “idempotent if app status already matches.” **False for reject:** reject writes `rejected` (`users.py:262`), then catalog C/Q1 PUT `enabled=false`, then webhook `ADMIN*` + `extract_enabled` (`keycloak_webhooks.py:248–250`) overwrites **`rejected` → `suspended`**. | high | findings | Lock the inbound state machine before planning, e.g. `enabled=false` only `active`→`suspended`; `enabled=true` only `suspended`→`active`; never touch `rejected` / `pending_*` / `deleted`. Echo after reject then becomes a no-op. KC Admin Enable remains recovery **only** from `suspended` (already the enable branch). |
| medium | findings | KP-style “IdP first, restore if DB commit fails” plus fail-closed “no app-only status” need an explicit order: DB row + commit vs Admin PUT vs logout vs execute-actions. A GET-merge-PUT between webhook delivery and commit can still race; general plan should say SELECT FOR UPDATE + ignore echo when actor is this service account (optional) **or** rely on the status-machine lock above. |

## Reusable mini-SaaS base — what else pays off

Goal of this review (user): a **cloneable** base, not a one-off console page. Do **not** replace this repo with a commercial starter (stack mismatch). Steal **capabilities**, keep FastAPI + React + Keycloak + workspaces.

### Do not buy / do not fork as the product

Closest public kits (2026 survey) — none are a drop-in for this template:

| Kit | Stack | Why not adopt as base |
|-----|--------|------------------------|
| [Rudra](https://github.com/subhrajit-mohanty/Rudra) | FastAPI + React + Keycloak + Mongo/Postgres | Closest **IdP** cousin; productized auth SaaS (plans, coupons, SDKs), not a generic workspace template. |
| [FastReact](https://fastreact.dev/) | FastAPI + React + Stripe | No Keycloak; built-in username/password. Ideas: usage metering, landing page. |
| [yezz123/ai-template](https://github.com/yezz123/ai-template) | FastAPI + Next + Authx | Workspaces, Stripe, audit, API keys behind `FEATURE_*`. Auth is not KC. |
| [fastapi-saas-starter-kit](https://github.com/bilalzulfiqar-pk/fastapi-saas-starter-kit) | FastAPI + Next | Cookie auth, workspaces, invites; **no** audit, Stripe, API keys. Weaker than this repo. |
| [LastSaaS](https://github.com/jonradoff/lastsaas) / SaaSQuickStart | Go + React | Full **platform admin** catalog (users, suspend, impersonate, CSV, health). Steal the **admin IA**, not the stack. |
| [SaaSWeave](https://github.com/mathias7799/SaaSWeave) | TS monorepo + Better Auth | Platform admin, impersonation policy, API keys, webhooks, maintenance mode. |

**Verdict:** keep saas-base. The gap vs paid kits is not “rewrite on Next/Clerk”; it is (1) platform **user** directory + IdP write path (this program), (2) **repeatable Keycloak**, (3) a short list of clone-every-time modules still deferred.

### Highest clone-speed ROI **after** this program (recommend as explicit follow-ons)

Ranked for “next product in a weekend,” not for a public SaaS kit:

1. **Realm-as-code** (if not absorbed into item I) — `deploy/keycloak` realm JSON or keycloak-config-cli. Without this, every clone re-clicks Admin Console. Highest leverage in the whole template.
2. **File upload adapter** (`SAAS_BASE_FINDINGS.md` Q22 deferred) — almost every product needs logos/exports/attachments. S3/R2 + one service + one settings tab. Kits (Kostra, SaaSWeave) all ship this.
3. **Personal API keys** (Q21 deferred) — required the moment a clone has a public API or Zapier. LastSaaS/SaaSWeave/ai-template treat this as base.
4. **Outbound webhooks** (user.created, workspace.suspended, etc.) + delivery log — B2B buyers expect it; this repo has inbound KC/Stripe only.
5. **Clone smoke script** — one command: realm import, client-credentials GET user, JIT `/me`, Mode A directory lists bootstrap SA. APP_REPLACE steps 1–7 stay documentation; a script makes clones real.
6. **Transactional email templates** — app already has Mailgun; Keycloak needs SMTP for Q15. Shared “from” domain + branded templates beats console `print`.
7. **CSV export** of admin user/workspace lists — cheap, present in LastSaaS/SaaSQuickStart; operators use it on day two.
